# clash-lianshi

Clash Verge / mihomo 链式代理的脱敏配置参考：使用自己的订阅节点作为前置，再连接独立的 SOCKS5 出口。

```text
本机 → 前置订阅节点 → SOCKS5 出口 → 目标服务
```

本仓库没有可用账号、真实出口地址或完整订阅，也不会自动修改你的 Clash Verge。

## 使用入口

1. 阅读 [整体配置说明](整体配置说明.md)，了解增强配置的导入与验证流程。
2. 参考 [SOCKS5 出口信息示例](SOCKS5出口信息示例.md)，通过环境变量准备自己的凭据。
3. 使用 `tools/render-proxies.py` 生成仓库外的私有代理增强；Python 工具需要 Python `3.9+`，只依赖标准库。
4. 将 `templates/groups.example.yaml` 导入当前订阅的分组增强。
5. 修改 `templates/chain.example.js` 中的主组名称，再导入脚本增强。
6. 保存、加载配置，并确认主组与前置组当前选择，实际测试出口。

补充阅读：[配置摘要](clash-verge-chain-config-summary.md)、[出口验证与质量评估](出口验证与质量评估.md)。

## 安全与验证边界

- 只使用自己有权使用的订阅和代理服务。
- 示例中的文档保留 IP 与认证占位符不可用于真实连接。
- 私有配置、真实 `.env`、订阅链接、运行日志和含认证的备份不要提交。
- 规则模式仍遵循原有分流规则，不保证所有程序或流量使用该出口。
- 原方案确认过 TCP 链路；UDP 曾出现超时，不能据配置开关宣称 UDP 已可用。
- 出口的地理信息不等于住宅属性、信誉或具体平台兼容性保证。

`.gitignore` 采用公开文件白名单，但不会清理已提交的敏感信息；曾公开的真实凭据应轮换。
